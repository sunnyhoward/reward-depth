## 4. New instruments (all cheap, all reusable)

- **`probefix/pf_leakage.py`** — chat-template leakage meter. Regex, no GPU. The pathology it catches
  (reply completes, then emits a fresh `user`/`assistant`/`<think>` turn and re-answers) was invisible
  to every prior meter and Qwen scored those generations 94.9–97.1 on coherence. Retroactive scan in
  `results/probefix/leakage_scan.json`: **every DPO/DPOP arm and base at 0.000**, MD arms 0.021–0.573.
- **`probefix/pf_cjudge.py`** — blind Claude judging harness (`batch`/`batchnew`/`merge`/`report`),
  rubric extracted from `pf_judge_all.py` **by AST** so the two judges cannot drift, items shuffled
  across arms and families so per-agent calibration cannot correlate with arm, unconditional and
  engaged-only scoring side by side.
- **`probefix/pf_handlabel.py`** — the blind hand-label protocol (sample writes `blind.json`, withholds
  `key.json`).
- **`GRAD_CKPT=1`** in `pf_train.py` — activation recomputation, semantically identical, default off.
  Needed because a late read backprops through more blocks. **Incompatible with `MODE=mdstack`.**

**0a. (ANSWERED 2026-08-18, NEGATIVE — `results/probefix/RESULTS_0818_STAGE1_SIDES.md`.)**
Δchosen is POSITIVE at five of six read points in both pooling modes and is the larger of the
two moves; stage 1 does not exploit the difference-only defect and `MD_FLOOR` has nothing to
repair in `MODE=probe`. The same run found the real mechanism: the refitted probe sits at
**cos 0.43** to the base preference axis (0.72 for the same recipe fitted with no training),
separates the base model *worse* than that control and the trained model **4× better**, while
the base-frame margin at the attach point does not move. Stage 1 builds a direction. Question
as originally posed, kept for the reasoning:

**0a. Does the difference-only defect explain STAGE 1's signature failure?** `MODE=probe` scores
`probe.score(d)` with `d = read(chosen) − read(rejected)` — **a difference, exactly like mean-diff**.
Its three anti-forging provisions (scale-free RMS read, continuous refit, saturation) block
*inflating the residual*; **none of them pins either side's absolute position**, so the channel
`pf_mdsides.py` caught in the mean-diff arms (`RESULTS_0817_MDSTACK.md` §2, `RESULTS_0817_MDFLOOR.md`
§1) is open in the probe objective too.

This may explain the project's most-repeated finding. `probefix/HANDOVER.md`: *stage 1 raises linear
decodability everywhere including the final block and installs nothing at the output.* **If stage 1
raises decodability by pushing the REJECTED side down rather than the chosen side up, the
dissociation is explained directly** — the probe reads a difference so it registers the gain;
generation depends on the chosen side, which never moved. Nobody has tested this.

*The run*: retrain stage 1 (`MODE=probe`, 300 steps, ~20 min — the B4 adapters did not survive the
box), then `probefix/pf_mdsides.py` on it, base frame, same 128 pairs. **Δchosen ≈ 0 with Δrejected
strongly negative confirms it.** If it holds, it reframes every stage-1 result in `probefix/RESULTS.md`
and is a paper section in its own right.

**0b. Does replay stop the floor wrecking the model — and is `REPLAY_LOSS=kl` the right anchor?**
Every mean-diff and floor arm ran `W_REPLAY=0`. The banked leakage scan already shows replay helping
in this exact arm family, at matched steps:

| arm | leakage |
|---|---|
| MD_L20 r0 (no replay) s300 | 0.146 |
| MD_L20 **r1 (replay)** s300 | **0.042** |
| MD_L20 r0 s600 | 0.271 |
| MD_L20 **r1 (replay)** s600 | **0.115** |

Replay halves-to-thirds the leakage — so it plausibly rescues the floor arms, which leak 0.625–0.896.
Two caveats: replay **costs install** (`MD_r1_s100` 58.0 vs `r0` 62.1 unconditional ff), and
`RESULTS_0814_REPLAY.md` established the term as configured is **not an anchor** —
`REPLAY_LOSS=nll` trains the policy to predict the replay corpus, which *increases* KL from base. It
suppresses pathologies by competing for gradient, not by holding the model still.

*The run*: **`REPLAY_LOSS=kl`** — implemented in the codebase and **never once used** — takes KL
against the adapter-disabled base on the same window, i.e. a real anchor. `MD_FLOOR=1 W_REPLAY=1
REPLAY_LOSS=kl` at L20, 300 steps, is the combination that tests "keep the absolute anchor without
wrecking the model". Pair it with the saturating floor in item 1 rather than running both separately.

**0c. Scope note for the write-up.** For *pure* decodability measurement (the L\* curves,
`dec_scalar`, `pf_probe_curve` on a frozen model) there is no pathology — nothing is being optimised.
But **every before/after decodability comparison on a TRAINED model inherits the ambiguity**: a rise
can be produced by either side moving, and no existing analysis in this repo distinguishes them.
`pf_mdsides.py` is the instrument that does, and it should be run beside any such claim from now on.

## 7. Traps added today

- **`pkill -f <pattern>` kills the tool wrapper**, because the wrapper shell carries the queued
  command text in its own cmdline. Already recorded in `NEXT.md` for `pgrep`; I hit it anyway and
  killed two training runs. Launch with `setsid`, record PIDs, kill by PID.
- **`dec`-style per-family read-depth probes are confounded** and must not be used
  (`probefix/pf_probe_curve_fam.py`, kept only so nobody re-runs it): `style` pairs differ in 81% of
  tokens and 13 tokens of length, so a mean-pooled embedding read separates them at **0.989 before
  any computation**. It measures pair separability, not rule depth.
- **A new mode inherits `PROBE_READ=last`** unless added to the default expression — pooling is
  load-bearing per phase 8, and `mdstack` silently ran with `last` on its first launch.
- **The GPU is shared** and the neighbouring session held 25 GiB. Late reads need more activation
  memory than early ones; `GRAD_CKPT=1` is the fix except under `mdstack`.
- **M0 must be recalibrated per read point** — base projections range 7.19 (L12) to 9.50 (L30), so a
  copied M0 is unreachable for some segments and already satisfied for others.
